# ログイン画面仕様

## 1. この文書の対象範囲

本書は、ログイン画面 `/login` の仕様を定義する。

共通の UI 方針は [../common.md](../common.md)、ログイン API の正本は [../../api/common.md](../../api/common.md) を参照する。

## 2. 画面概要

ログイン画面は、ユーザー名とパスワードを入力し、バックエンドのログイン API を通じて認証を行う画面である。

## 3. URL

- 画面 URL は `/login` とする

## 4. 入力項目

- `username`: ユーザー名
- `password`: パスワード

入力項目は上記 2 項目のみとし、ワンタイムパスワードや 2 要素認証は行わない。

## 5. ログインボタン

- ログイン画面にはログインボタンを配置する
- `username` と `password` の両方が入力されるまでは、ログインボタンは無効状態とする
- `username` と `password` の両方が入力された場合にのみ、ログインボタンをクリック可能とする

## 6. 送信動作

- ユーザーがログイン操作を行うと、UI はバックエンドの `POST /api/auth/login` を呼び出す
- リクエスト本文には `username` と `password` を含める
- ログイン処理自体はバックエンド API で実行する

## 7. 成功時の挙動

- バックエンドは Cookie セッションを確立する
- UI はログイン成功後に `/` へリダイレクトする

## 8. 失敗時の挙動

- 入力不備の場合は、入力内容の見直しが必要であることを画面上で通知する
- 認証失敗の場合は、ユーザー名またはパスワードが正しくないことを画面上で通知する

## 9. 範囲外

- ユーザー登録機能
- ワンタイムパスワード
- 2 要素認証
- ログアウト機能
