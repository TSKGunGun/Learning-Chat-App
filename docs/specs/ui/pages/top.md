# トップ画面仕様

## 1. この文書の対象範囲

本書は、トップ画面 `/` の仕様を定義する。

共通の UI 方針は [../common.md](../common.md) を参照する。

## 2. 画面概要

トップ画面は、ログイン成功後にリダイレクトされて表示される画面である。
ログイン済みユーザーのチャット一覧を左側サイドバーに表示し、右側にチャット画面を常設表示する。既存チャットを開く、新規チャットを開始する、チャットを削除する操作を提供する。

## 3. 表示内容

- 左側サイドバー
- 右側チャット画面
- モバイル用サイドバー開閉操作

チャット一覧は、バックエンドの `GET /api/chats` を用いて取得する。
チャット一覧には、各チャットの `channel_id`、チャンネル名、`last_messaged_at` を表示対象データとして保持し、UI 表示ではチャンネル名を表示する。
削除済みのチャットチャンネルは一覧に表示しない。
未保存の新規チャットは一覧に含めず、右側チャット画面内でのみ `新規チャット` として扱う。
チャット画面内でメッセージ送信またはポーリング更新が行われた場合、トップ画面は `last_messaged_at` と `channel_name` の更新に追従するためチャット一覧データをリフレッシュする。

左側サイドバーには以下を表示する。

- 新規チャット開始ボタン
- ログイン済みユーザーのチャットチャンネル一覧
- 各チャットに対応する削除ボタン

右側チャット画面には以下を表示する。

- 選択中チャットの見出し
- 選択中チャットのチャット履歴
- 未保存の新規チャット状態
- メッセージ入力欄と送信操作
- `sender_type = ai` かつ `status = completed` のメッセージに対する Good / Bad フィードバック

トップ画面初期表示時の右ペインは次で固定する。

- チャット一覧が 1 件以上ある場合は、`last_messaged_at` 降順の先頭チャットを自動表示する
- チャット一覧が 0 件の場合は、未保存の新規チャット入力可能状態を表示する

モバイル幅では、右側チャット画面を主表示とし、チャット一覧はドロワー型サイドバーで開閉する。

## 4. ボタンと操作

### 新規チャット開始ボタン

- トップ画面には新規チャット開始ボタンを配置する
- ユーザーが新規チャット開始ボタンを押下すると、UI は右側チャット画面を未保存状態の新規チャット表示へ切り替える
- この時点では `chat_channels` はまだ生成しない
- 最初のメッセージ送信時に `POST /api/chats` を呼び出し、チャットチャンネル生成と初回メッセージ送信を同時に行う
- 初回送信成功後は、返却された `channel_id` と `channel_name` を右側チャット画面へ反映し、以後は保存済みチャットとして扱う

### 既存チャットを開くボタン

- チャット一覧の各項目は選択可能なチャットチャンネル行として表示する
- ユーザーがチャット一覧項目を選択すると、対象チャットを右側チャット画面へ表示する
- 対象チャットの表示には `GET /api/chats/{channel_id}` を利用する前提とする
- 既存チャットを選択した場合、右側チャット画面内に対象チャットのチャット履歴を表示する
- 選択したチャットに `status = pending` の AI メッセージが存在する場合は、その時点でポーリングを開始する
- モバイル時は、チャット一覧選択後にドロワーを閉じて右側チャット画面へ戻る

### チャット削除ボタン

- チャット一覧の各項目に、チャット削除ボタンを配置する
- ユーザーが削除ボタンを押下すると、UI は `DELETE /api/chats/{channel_id}` を呼び出す
- 削除成功後、対象チャットは一覧から除外される
- 削除対象が現在選択中でない場合、右側チャット画面の表示は維持する
- 削除対象が現在選択中である場合、右側チャット画面は次の表示対象へ切り替える
- 次の表示対象は、更新後一覧の `last_messaged_at` 降順の先頭チャットを優先する
- 切り替え先が存在しない場合、右側チャット画面は未保存の新規チャット入力可能状態へ切り替える

## 5. 右側チャット画面の挙動

- 未保存の新規チャット状態では、右側チャット画面に `新規チャット` の見出しと空の履歴を表示する
- 保存済みチャット状態では、`channel_name` を見出しとして表示する
- `POST /api/chats` または `POST /api/chats/{channel_id}/messages` の成功レスポンスに `channel_name` が含まれる場合、右側チャット画面の見出しはその時点で即時更新する
- `sender_type = ai` かつ `status = pending` のメッセージは「AI回答生成中」と表示する
- `sender_type = ai` かつ `status = completed` のメッセージは `message_text` を表示する
- `sender_type = ai` かつ `status = ai_timeout` のメッセージは `AI応答がありません` を表示する
- `sender_type = user` のメッセージは `status` を無視して `message_text` を表示する
- `sender_type = ai` かつ `status = completed` のメッセージに対してのみ Good / Bad フィードバックを表示する
- `status = pending` または `status = ai_timeout` の AI メッセージにはフィードバックを表示しない
- `status = pending` の AI メッセージが存在する間は、入力欄と送信操作を無効化する
- 定期再取得は 1 秒間隔とする
- 定期再取得は、対象チャット内に `status = pending` の AI メッセージがなくなった時点、または右側チャット画面が別チャットや未保存新規状態へ切り替わった時点で停止する
- `status = completed` または `status = ai_timeout` をポーリングで検知した場合、右側チャット画面更新に加えてチャット一覧データもリフレッシュする

## 6. 遷移

- ログイン成功後、UI は `/` へリダイレクトする
- 未認証状態で本画面にアクセスした場合、UI は `/login` へリダイレクトする

本画面の詳細なレイアウトは、現時点では本仕様の対象外とする
